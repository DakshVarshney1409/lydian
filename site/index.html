How it plugs in

One object per step.
That's the whole contract.

Lydian reads a trace as a list of steps: which node ran and what it produced. The judge reads that, the question, and the final answer, and names the step that broke.

trace.json — one object per step
[
  { "node": "intent",    "output": "new_claim",
    "topics": ["filing"] },
  { "node": "retriever", "output": ["POL-CLAIM-FILE"] },
  { "node": "reasoner",  "confidence": "high" },
  { "node": "responder", "hedged": false }
]
Minimum

A node name and its output. Anything else you pass through gets used.

Any model

Anthropic, OpenAI, or any OpenAI-compatible endpoint, including a model running on your own machine.

Frameworks

Export your trace to this shape from any framework. Built-in adapters for LangGraph, LlamaIndex and OpenTelemetry are coming next.

Time to first result

Clone, add a key, run the benchmark. A few minutes.

Run it yourself

Open source and MIT licensed. It runs on your machine with your own API key. Traces go only to the model provider you configure.

No hosted service

There is no Lydian server collecting your traces. Results are written to a local file, and nothing is kept beyond that.

How we're different

Other tools give you a score. We tell you which node to fix.

Tracing and eval platforms are good at recording what your agent did and grading what came out. They stop at "this answer scored 2/5". Lydian starts there.

When…Typical eval & observability platformLydian
An answer is wrong Typical platformA low score on the final output and a long trace for someone to read. LydianThe node that caused it, why, and a fix. Every other node is explicitly cleared.
You adopt it Typical platformInstrument with their SDK, then do your work inside their platform. LydianReads a node-by-node trace. No SDK lock-in, and it runs on your own machine.

You don't have to switch. Keep the tracing tool you have. Lydian reads the same traces and answers the question it leaves open: which part do I change?

You already have AI engineers

They can debug it. That was never the problem.

Lydian isn't a substitute for that skill. It exists because of what the skill costs, and what it never gets pointed at.

Cost

Diagnosis competes with shipping

Every incident quietly converts a build day into an investigation day. Nobody puts that on the roadmap.

Coverage

You only debug what you hear about

The confidently wrong answer nobody escalated stays wrong. A suite runs on all of it, every time.

Regression

Nobody re-checks the forty cases that worked

A prompt edit to fix one complaint is the most common way a working agent breaks.

Evidence

It ends the retrieval-vs-prompt argument

Two engineers disagreeing is expensive and unresolvable by opinion. A verdict with the innocent nodes cleared settles it.

An attention and evidence gap, not a skill gap. Strong teams have it too — they just fix the node in an hour once they know which one, instead of spending the hour finding out.
